# T0-GATE-ID-UNIQUENESS

## 起因（实测，2026-08-23）

同一天里**三个会话各自给自己的新闸取了 `2d`**：`T0-LESSONS-BUMP-PLANE`(#129)、
`T0-LESSONS-COLD-RECALL`(#51)、`T0-LESSONS-CAP-UNIT`(#127)。每个都按「扫一眼、取下一个空号」
做的，每个在自己那棵树上都对。#129 先合，另两个才在合并时暴露。

**harness 全程没有察觉**。撞号不是文本冲突——两个同名闸会**都跑**，而失败文案说不清是哪一个；
如果两者恰好都在 core 分片，读日志的人只会看到「闸2d 失败」而无从判断是哪一道守卫红了。

人工协调这次解决了它（`2d` 留给已合并的 #129，另两张改 `2f`/`2g` 与 `2a`/`2h`，下一个空号 `2i`），
但**根因没动**：闸号靠人脑与各自本地文件追踪，没有任何机检。下一次并行窗口会再来一遍。

## 顺带治的第二类：按锚点拼接的静默错位

同一天两次合并各丢过一次闭合花括号。`Parser::ParseFile` 都当场抓到了（**这是本卡 A8 的依据**：
它是即时的，跑一次的代价可以忽略）。但它报的行号离真实缝口很远——一次报 1238、缝在 1740，
一次报 1836、缝在两百行外——所以「报错行号」不能当定位用。

更坏的一次它抓不到：**锚点不唯一**。用于插入的字符串同时出现在某个闸的头部摘要里，于是新块落到了
它依赖的变量声明之上。语法完全合法，parse 全绿，只有执行到 StrictMode 才炸。故 A7 要求锚点唯一性
本身成为断言——这类错误的特征就是「看起来完全正常」。

## 为什么不用豁免清单

`forbid` 明写禁止。一旦允许「已知重复」登记豁免，下一次撞号就会被登记进去而不是被修掉，
断言退化成台账。撞号本身就是要被报出来的事实，没有合法的重复。

## 为什么负控是必须的（A6）

「没有找到重复」和「什么都没扫到」在退出码上不可分辨。这正是本仓 L165 反复要治的形态：
断言宽于契约、或者根本没打到靶，都表现为绿。A6 把扫描面非空做成显式断言。

改写成「撞号已解决，但根因是无机检」，并明说该修法无人认领。修法内容按其建议实现。
