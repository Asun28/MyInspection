配置层 single config point

唯一配置点 scripts/_config.ps1

GhAccount · FrozenPaths · ProjectTier · PythonVersion · ScaffoldOriginVersion（不可变生成来源）· ScaffoldVersion（已裁决高水位）等项目级常量集中于此；每个脚本与钩子 dot-source 它取值，绝不硬编码。

执行闭环 single-card loop R1-R5

task-loop task.ps1 R1-R5

每张卡一个 agent、一棵 git worktree，并行跑：worktree → TDD（red 证据）→ 剪枝 → 许可 / 防泄露闸 → 第二模型评审 → PR → 合并 → 文档同步。无远端 / 无 Codex 时 -Local 本地完成。

消费任务卡

worktree 并行窗口 WorktreeRoot

冻结点卡先合，其余卡在各自 worktree 并行推进互不阻塞。根目录由 _config 配置。

质量闸 · 确定性 deterministic gates

check-cards check-cards.ps1

校验任务卡：id=文件名、status 枚举、branch/worktree 不漂移、dod_command / allow_paths 完整、拒卡文占位符 token 字面量（L61/TD111）。

范围闸 _scope.ps1 · check-scope.ps1

改动是否全在卡 allow_paths 内：段级前缀匹配（非字符前缀）、含通配符的 allow 条目字面保真、禁改名折叠、CJK 路径不 C-quote；越界与不可判（allow 取不到 / 基线不可解析 / diff 失败）皆 fail-closed。判定核由 ship 内联闸与独立入口 check-scope.ps1 共用——后者给「已推送状态的手工恢复」序列一条有退出码的命令（CI 没有范围闸，那条序列此前只是散文）。

一枚核 · 两个入口

第二评审 · 独立模型 review.ps1

按 QUALITY-RUBRIC 判、反自我开脱、不确定即 block；写审分离的第二独立模型（当前 = codex）。fail-closed 新鲜度守卫：评审者非零退出 / 裁决 sha≠HEAD / 旧裁决未刷新即 block。状态名取自 _config 的 ReviewStatusContext（可换后端，不再硬编码）。模型与推理档位同样取自 _config（ReviewModel / ReviewEffort，留空=后端默认），免疫用户级 ~/.codex/config.toml 被 GUI 改写而使合并闸静默失效。阻断态可诊断（TD96）：「跑完了但读不出可用裁决」拆成四态，各带 ASCII 状态码与恢复路由（rubric §5），分类器拒答那态把评审者原文另存 .review/(分支名).raw.txt；裁决存不下来即 block；裁决产物叶子、.review 或其任一祖先是重解析点时即拒（启动与唤起前各判一次，检出后零产物操作、不唤起评审者）。

独立于写码模型

CI verify verify.ps1 · ci.yml

确定性 CI 闸：windows-latest（T0-TOOLCHAIN 起：Android/Gradle 闸与开发机同源、以确定性换 2× 计费分钟）、无密钥；网络仅限引导步（setup-java / setup-android / 一次在线 gradlew build 预热缓存），此后各闸恒 --offline。job 名 verify，含占位「闸门 2」接 e2e。触发 push + pull_request（[main, master]，selftest 8.2d 锁形态）；push 侧为事后检测——提交落地后才跑，非 push 前强制（后者归 pre-push 钩子 / Pro-public 规则集）。

商用许可闸 check-licenses.ps1

扫 PyPI / npm 许可，把不兼容许可挡在合并前。

防泄露闸 check-secrets.ps1

敏感模式集单一真相源；查已追踪敏感文件 + 硬编码密钥（snake_case / 无引号 / UTF-16）。已接入 task.ps1 ship（提交后、推送前阻断）；变 public 前 -Strict 扫历史须全绿。

元仓总自检 selftest.ps1

17 闸一把跑全：本地默认仍把 core（1–14+16）、workflow（15）、seeded（完整 17）放入三份独立仓库快照；两个长分片先并行，短 core 在 75 秒后以低优先级错峰加入。任一分片非零即总闸非零。CI 为压住 20 分钟预算，把 seeded 等价拆成 git/remote/scanner 三片，在 Windows/Ubuntu 各跑 core、workflow 与三片 seeded，共 10 个独立 runner job，覆盖不减。它们只在默认分支 push 命中非 Markdown 脚手架权威面或手动触发时启动，作为合并后 canary；PR 保留任务卡 DoD、verify 与 R3，不运行本辅助工作流。检查包括语法 / 经验 / 模板哨兵 / token 覆盖 / 裁决漂移 / 交叉链接 / 计数一致 / 动态 E2E / 种子缺陷（拿已知坏输入验证每道闸真会拦）等。约 12 闸测的是随下游保留的生产脚本（task.ps1/review.ps1/...），init 不再删它，元仓专属子闸检测到已初始化会自跳过（TD15）。

关键关系连线 · key wires

架构的真相在接线，不在盒子。悬停或键盘聚焦任一子系统会点亮它的关系组：

  • _config 喂所有脚本：唯一配置点向上贯穿每一层，留空即各守卫优雅降级。
  • plan-forge → 任务卡 → task-loop：计划投影成卡，卡被执行闭环消费。
  • lessons ↔ HARNESS-REVIEW：judgment 经验喂减法评审，评审结果再回流经验库。
  • triage 只读扫各子系统：心跳横切所有层，只发现、不行动、恒退出 0。
  • codex = 第二独立模型：写码与评审分离，review.ps1 的裁决独立于实现模型。
  • frontend-flow → plan-forge / grill-design：前端不另造引擎，复用漏斗的拷问与投影。

提示：移开指针 / 移走焦点即恢复全局视图；偏好减少动态时不做明暗切换，盒子始终全可读。
