想法 → 计划 → 上线 Idea → Plan → Ship · the full pipeline, front funnel to shipped & verified

一句话想法怎样一步步变成可开工的任务卡、并行跑成可运行产品，再经验收、收口、防泄露后上线。机器做搜集、打分、投影、验收，不替你拍板。下方左缘那条会变色的脊柱，就是贯穿全程的方法主线：＋ 加法 → − 减法 → × 乘法，最后汇入一段薄荷色的验收尾段。

合并之后 验收 → 收口 → 发布 verify · close-out · release AI 跑闸 · 人批发布

产品跑起来不等于做完。三道确定性收口闸把「可运行」推到「可上线」。

1

eval 方法论 docs/EVAL.md · opt-in

确定性 exit-0/1 eval 标准（点击→路由 / MCP 契约 / 安全闸 / 功能黄金集）；LLM-judge 留上游、不当闸。本仓不带 runner，下游按标准自建、自接 CI。

2

发布前收口清单 docs/RELEASE-CHECKLIST.md

可勾选清单：整合已有闸（防泄露 / verify）+ 授权认证自查（越权 IDOR / 会话固定 / token 存储 / CSRF / 密码哈希）+ 可观测（结构化日志 / 脱敏）+ 灰度 / 回滚。小项目取子集。

3

变 public 前防泄露闸 check-secrets.ps1 -Strict

核心数据库 / 密钥 / 凭据须既被 gitignore、又未被 git 追踪（已追踪文件 gitignore 救不了 → git rm --cached）。-Strict 须全绿才可变 public。

⛳
人批发布 三闸全绿后由人定上线

合并之后的交付 / 运维方法论（集成 / e2e · 结构化日志 · 灰度 / flag · CD 部署 / 回滚）见 docs/DELIVERY-OPS.md（T2 · opt-in）。脚手架永不自动发布，CD 由下游接线。
