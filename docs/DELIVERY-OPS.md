# 合并之后 · 交付/运维方法论（DELIVERY-OPS）

> 脚手架的核心优势是 **想法→合并**（build-time）：worktree+TDD+Codex 评审+CI 把「这次改动对不对」钉死。
> 本文件是它的**合并之后**姊妹篇——一个**可选叠加层（opt-in）**，补齐「代码合进 main 之后」的四件事。
> 全篇是**方法论 + 标准 + 占位**，工具无关（L26：方法论优先于工具，具体工具仅作举例/按需）。
> **硬边界不变**（见 `docs/SECURITY.md`）：脚手架**永不自动发布**；真正的部署接线由**下游**按自己平台补，CD 是 opt-in。
>
> 配套接入点：`scripts/verify.ps1` 闸门 2（集成/e2e 占位）· `docs/EVAL.md`（eval 四维）· `docs/PLAN-TEMPLATE.md`（计划占位节）· `docs/QUALITY-RUBRIC.md`（R3 结构化日志维度）。
> 文档漂移闸的设计与豁免约定见 `docs/adr/0005-doc-drift-gate.md`。
>
> **本文是三层回路的第 ③ 层**（external feedback：真实用户 / A-B / 生产数据）。层间分工、闸门密度倒挂的取舍、以及
> ③ 信号回流 ①② 的两条正门（缺陷类→eval GROW；方向类→漏斗 `1-brief`），正文在 `docs/LOOP-ENGINEERING.md`「三层回路」节。

## a. 集成 / e2e 测试层

单元测试（TDD）保的是「每块零件对」，**不等于**「装起来跑得通」。装配后的主流程、模块接缝必须另有覆盖：
**集成测试**用 mock 数据验模块间契约与装配；**e2e** 打一个测试环境跑真实端到端旅程。

**标准**：主用户旅程 + 关键模块接缝，在判「done」之前必须有一条集成/e2e eval 兜底，不只靠单卡 DoD。
这些就落在 `scripts/verify.ps1` 闸门 2 与 `docs/EVAL.md` 的 `frontend-behavior` / `backend-mcp` / `functional` 维度里
（确定性 exit 0/1，LLM-judge 留上游不当闸）。工具作举例：前端如 Playwright、后端如 pytest，**非必须**。

## b. 结构化日志 / 可观测

**标准**：关键路径与错误分支打**结构化日志（JSON）**，每条必带**请求ID / 用户ID / 关键参数**——让 Agent
能仅凭日志**还原现场**。禁止裸 `print`。机密（cookie/token/密钥）在落盘前脱敏（与 `docs/SECURITY.md`「结构化日志脱敏」一致）。

这是「线上问题自动化修复」的地基：日志能还原现场，Agent 才能定位→复现→修。日志后端 / sink（控制台 / 文件 / 如
OpenTelemetry / 云日志服务）是**下游的选择**，本层只规定字段契约与脱敏，不绑实现。R3 评审会按 `docs/QUALITY-RUBRIC.md` 检查此维度。

## c. 灰度发布 + feature-flag

**方法论**：新功能藏在 flag 后上线 → 先内部/小流量 → 逐步放量 → 出事用 flag **一键关停（不重新部署）**。
flag 把「发布」和「上线」解耦，让回滚的代价从「重新部署」降到「翻个开关」。

**标准**：有风险的 / 面向用户的功能由 flag 闸门控制；功能稳定后**移除该 flag**（别让死 flag 堆积成债，转 `specs/tech-debt-tracker.md`）。
flag 库（如 LaunchDarkly、或自建一张配置表）是**下游的选择**，本层只规定「风险功能须可一键关停且可摘除」。

## d. CD：部署 / 发布 / 回滚 + 重现 / staging 环境

**方法论**：自动化部署 + **快速回滚**（回滚速度直接框定一次事故的爆炸半径——回滚越快，影响越小）；
另备一个**贴近生产的测试环境**（staging / 重现环境），在动手修之前**先复现并验证**线上问题。

**标准**：每次发布都有一条**自动化回滚路径**；修线上 bug 前先有可复现该 bug 的环境。

**占位**：与 `scripts/verify.ps1` 闸门 2 同理，本层只留一道**清晰的「在此接你的平台」接缝**，**不绑** Vercel / k8s / 云函数。
重申硬边界：**脚手架不自动发布**，CD 是 opt-in，下游接线后才生效。
