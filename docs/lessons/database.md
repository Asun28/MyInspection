# 数据库 / Schema 设计纪律（Tier2 · 按需读）

> 关系型数据库 schema 的**设计**纪律——补足脚手架原本只覆盖「schema 当契约冻结」(`FrozenPaths`/rubric#3)
> 与「跨层同构」(plan-forge `consistency` lens)、却不教「怎么把 schema 设计好」的空白。
> 何时读：设计或评审数据库表结构、ER、迁移时。机械接点见末节。
>
> **工具无关声明（L26）**：下面的具体默认（MySQL8 / Snowflake BIGINT / utf8mb4 / DECIMAL / UUIDv7·ULID）
> 是**当前默认 / 举例**，项目已有约定即从其约定；审计/评审看的是**标准是否被满足**，不绑定某引擎。

## 强制设计纪律（建模在前，DDL 在后）
- **先业务后表**：先识别领域对象（实体/值对象/事件/日志/配置），每张表能一句话说清「为什么存在、由哪个业务流程负责」；别因为提示词里出现名词就建表。
- **规范化**：事务型默认 3NF；只有明确读路径/报表/扩展性需求才反规范化，且必须写明数据源 + 同步策略。
- **主键策略**：业务表用**稳定代理主键**；规模化/分布式默认 Snowflake `BIGINT`（或 `UUIDv7`/`ULID`），小型单库才 `AUTO_INCREMENT`；**绝不**用 email/手机/SKU/单号等可变业务标识做主键。
- **审计/生命周期字段**：业务表标配 `created_at/by`、`updated_at/by`、软删除 `deleted`（需删除时间再加 `deleted_at`）。
- **状态字段**：每个 `status`/`state` 必须定义 **全部取值 + 合法流转 + 终态**（写注释/数据字典）；可配置/需国际化的用字典表，稳定常量用小整数编码。
- **关系**：标基数（1:1 / 1:N / N:M）与 所有权 vs 引用；N:M 用关联表（关系有属性就放关联表上）。

## 高频陷阱（已入账 LEDGER，会复发）
- **[L42] 软删除唯一索引必须含 `deleted`**：否则删后无法重建同值 / 唯一冲突＝静默数据损坏。（PG 用部分索引 `WHERE deleted=0`）
- **[L43] 金额用 `DECIMAL` 非 `FLOAT`/`DOUBLE`**：浮点不能精确表示十进制金额；多币种显式存币种。
- **[L44] 业务逻辑禁入触发器/存储过程/DB 事件**：隐藏副作用（一个 insert 偷偷扣库存/发消息）难追难测难迁移；业务逻辑放 service/领域层；触发器仅作文档化例外。
- **[L45] 逻辑外键默认，跨库/跨服务禁物理外键**：存引用字段 + 给引用列建索引 + 应用层保完整性；物理 FK 仅小型单库。

## 命名（项目无既有约定时）
- 表：`snake_case` + 复数（`users`/`order_items`）。字段：`snake_case`；外键/引用 `{entity}_id`。
- 索引：`idx_{table}_{cols}`；唯一：`uk_{table}_{cols}`；物理外键（若用）：`fk_{child}_{parent}`。
- 不混用 `UserID`/`userId`/`tbl_user`。

## 数据类型
- ID：Snowflake→`BIGINT`；UUID→`BINARY(16)`(MySQL)/`UUID`(PG)。可能增长的表别用 `INT`。
- 时间：持久化用 UTC，明确时区语义。MySQL 字符集 `utf8mb4`（非 `utf8`，否则丢 Emoji）。
- JSON：仅放稀疏元数据/集成载荷；核心可查询字段别藏进 JSON（PG 用 `JSONB`，高频路径用生成列/表达式索引）。
- 枚举：整数编码 + 注释或字典表；避免 DB `ENUM`（迁移成本高）。

## 索引（来自查询场景，不是字段名）
- 为高频等值过滤、引用列、状态+时间、范围、排序分页、唯一业务标识建索引。
- 组合索引顺序：**等值 > 范围 > 排序**；多租户表 `tenant_id` 最左。
- 避免：每字段都建、重复索引、索引列上用函数（`DATE(created_at)=?`）、大表前置通配 `LIKE '%x%'`。

## 反模式速识
EAV 三元组 · 逗号分隔值列 · 100+ 字段宽表 · ENUM 滥用 · 自引用递归层级查子树 · `DEFAULT 0` 混淆「未设置」与「真 0」。
