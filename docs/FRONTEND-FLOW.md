# 前端生成闭环（FRONTEND-FLOW）—— 方法论 + 流程卡/意图卡模板

> **给谁看**：要做**复杂多页前端**(T2 档)的人/AI。把「需求 → 页面 → 任务卡 → 高保真 → 上线 → 沉淀」串成四段闭环。
> **核心立场**：本闭环**不造新引擎**——每段都复用本仓已有的件;它只补「前端生成」这个串联视角。
> 触发驱动卡:`.claude/skills/frontend-flow`。档位:仅 **T2**(简单单页前端别上,直接 `frontend-design` + pencil)——见 `docs/IDEA-TO-PLAN.md` 档位表 + 反过度工程。

## 四段闭环（每段复用哪个现有件）

| 段 | 干什么 | 复用现有件（不重造） |
|---|---|---|
| **1 生成前** | 定 PRD、定生成规则、定组件底座 | PRD = `shape-idea`/`docs/PROJECT-BRIEF-TEMPLATE.md`(+可选前端补充节) · 生成规则 = `frontend/README.md` 5 闸 + design tokens 真相源 · 组件底座 = `frontend/` + tokens(下游填) |
| **2 生成中** | 产出**流程卡(页面地图)** + **意图卡(单页目标)** | 流程卡页面清单 → 喂 `.claude/workflows/plan-forge.mjs` 投影任务卡(复用 DAG 拆解/卡审) · 意图卡 → 用 `.claude/skills/grill-design` 拷问敲定(复用交互式拷问) |
| **3 生成后** | 可视化高保真、局部 AI 改、导出 | 可视化 = **pencil MCP**(现成 `.pen` 编辑器)/ Claude Design / v0(路由,不自造) · 局部改 = `frontend-design`/`taste-skill` · 导出 = 正常 React 工程 |
| **4 资产回流** | 验证过的区块/页面沉淀复用 | `context/frontend-assets/`(含元信息;只沉淀模式/约定,业务实现仍在 `frontend/`) |

> **边界(复用非重复)**:流程卡 ≠ plan-forge 任务 DAG(前者 UX 页面关系、后者施工依赖,前者**喂**后者);意图卡 = grill-design 的前端产物模板;资产库 = `context/` 的前端子集;可视化编辑只**路由**到 pencil/Claude Design/v0(L26 工具可换,选了记 lesson/ADR);生成规则不另立、直指 `frontend/README.md` 5 闸。

## 第 1 段 · 生成前

### PRD（可选前端补充节）
主 PRD 仍是 `shape-idea` 产出的 `_local/1-brief.md`(模板 `docs/PROJECT-BRIEF-TEMPLATE.md`)。复杂前端可在其后追加一节：

```
## 前端补充（仅 T2 复杂前端填）
- 目标用户的设备 / 场景：<桌面为主 / 移动优先 / 兼顾；网络/无障碍约束>
- 核心页面假设（先粗列，后由流程卡细化）：<登录 / 仪表盘 / 详情 / 设置 …>
- 品牌 / 视觉约束：<已有 design tokens？品牌色？参考产品？无则交设计层定>
- 关键交互假设：<实时？拖拽？大表单？数据密集？>
```

### 生成规则（不可漂移）
直接套 `frontend/README.md` 的 **5 道闸**——生成的每个页面都要过：① 命名 eslint+tsc · ② 接口单一真相源(字段从后端契约生成类型,**禁前端手写后端字段**) · ③ plan-forge consistency · ④ webapp-testing 契约断言 · ⑤ **design tokens 视觉真相源**(颜色/间距/圆角走 token,禁魔法值)。

## 第 2 段 · 生成中（核心产物）

### 流程卡模板（页面地图 · 整个前端一张）
> 用途:把整个前端的页面与关系画清楚。填完→**喂 plan-forge**,页面清单投影成带依赖的任务卡。

```
# 流程卡 · <项目名> 页面地图

## 页面清单（路由 → 用途）
| 路由 | 页面名 | 用途（一句话） | 关键数据来源（API/契约） |
|---|---|---|---|
| /            | 首页/仪表盘 | … | … |
| /items/:id   | 详情页      | … | … |
| /settings    | 设置        | … | … |

## 导航跳转关系
- <从哪页 → 到哪页，触发条件>（如：仪表盘卡片点击 → /items/:id）
- …

## 跨页共享数据 / 状态
- <状态名：谁写、谁读、存哪（URL/全局 store/服务端）>（如：当前用户 = 登录后全局，多页只读）
- …

## 入口 / 默认页
- 默认落地：<路由>　未登录重定向：<路由>
```

> **流程卡 → plan-forge**：把「页面清单」作为任务章节喂 `plan-forge.mjs`,它按页面/页面群拆成带 `depends_on` 的任务卡(共享状态/契约那张卡是冻结点,先于依赖它的页面卡)。**plan-forge 负责拆解与卡审,流程卡只给它 UX 视角的输入。**

### 意图卡模板（单页目标 · 每页一张）
> 用途:单页设计决策的产出形态。用 `grill-design` 拷问敲定(沿决策树一次一问、每问给推荐),别一次性脑补。

```
# 意图卡 · <页面名>（路由：<route>）

- **目标**：这页让用户能<做什么>（一句话，从用户视角，不写技术名词）
- **职责边界**：这页负责 <…>；不负责 <…>（明确不做什么，防页面膨胀）
- **关键交互**：<点击/输入/拖拽/筛选… 各自的预期反馈>
- **数据需求**：读 <哪些 API/字段>；写 <哪些 API/字段>
  （字段名接 frontend 闸 2 —— 从后端契约生成的类型，禁手写后端字段）
- **复用区块**：用 context/frontend-assets/ 的 <资产名…>（无则留空，验证后回流）
- **验收**：<点击 X → 路由到 Y / 渲染出 Z 字段>（可机检，接 eval frontend-behavior：点击→路由断言）
```

> **意图卡 ← grill-design**：每页填卡前说「grill 这页的设计」,grill-design 会沿「目标→数据需求→交互→边界」逐项问、给推荐、消解依赖。**拷问机制是 grill-design 的,意图卡只是它在单页上的产物模板。**

## 第 3 段 · 生成后
- **可视化高保真**：路由到 **pencil MCP**(现成 `.pen` 编辑器)或 Claude Design / v0(L26:举例不绑死,选了记 lesson/ADR)。
- **局部 AI 改 / 反 slop**：`frontend-design`(路由) / `taste-skill`。
- **设计保真 QA(spec vs render · 上游辅助,非确定性闸 · L25)**：当**同时有**[源视觉目标](本段产出的 pencil `.pen` 节点 / Claude Design 稿 / 批准的 mockup 或截图)**与**[已渲染实现](真跑的页面)时,**交付前**做一次保真比对——补上「闸 4 只断言数据键名、不管视觉是否忠于设计稿」这个缺口。
  - **机制**:对齐同一视口/主题/状态后,沿 **5 个保真面**逐面比:① 排版(字族/字重/字号/行高/层级)· ② 间距·布局(对齐/边距/栅格/纵向节奏)· ③ 色与 token(调色板/渐变/对比度/语义态色)· ④ 图像质量(锐度/裁切/压缩;**图被代码近似替代 = 失败**)· ⑤ 文案(应用内文本准确)。
  - **评级 + 产出**:每条偏差记 **P0**(阻断核心用途)/ **P1**(用户会注意到的明显失配)/ **P2**(中度视觉漂移或响应式问题)/ **P3**(小精修);汇总 `passed`(无未决 P0/P1/P2)或 `blocked`(点名阻断项)。产物落 `_local/`。
  - **取证(工具举例,可换 · L26)**:渲染侧截图走 `webapp-testing`,设计侧截图走 pencil MCP `get_screenshot`。**模型只在闸上游做比对判断,绝不替代 exit 0/1 的确定性 DoD**——与闸 4 / `verify.ps1` 同守 L25:视觉比对是「上游辅助评审」,不是可机检的验收闸。
- **导出**：正常 React(或所选框架)工程,不锁私有格式。

## 第 4 段 · 资产回流
验证过的区块/页面 → 沉淀到 `context/frontend-assets/`(元信息见该目录 `README.md`)。**只沉淀模式/约定/元信息,业务组件实现仍在 `frontend/`**(`context/` = 领域知识,不是组件仓)。

## 闭合
`想法 → 1-brief(+前端补充) → 流程卡(页面地图) → plan-forge 投影任务卡 → 逐卡施工(意图卡 ← grill-design 敲定每页) → pencil/设计层高保真 → 5 闸验收 → 上线 → 验证过的区块回流 context/frontend-assets/`。
